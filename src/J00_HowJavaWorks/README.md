# 1. The Complete Journey of a Java Program

Let's start with the bigger picture.

When I write a Java program, the computer cannot directly execute the human-readable Java source code in the same way that I write it.

Java uses a compilation and execution process.

The basic journey looks like this:

```text
       Java Source Code
           Main.java
               |
               |
               v
       Java Compiler
           javac
               |
               |
               v
        Java Bytecode
           Main.class
               |
               |
               v
              JVM
               |
               |
               v
       Program Execution
               |
               |
               v
             Output
```

There are two major stages:

1. Compilation
2. Execution (Runtime)

Before understanding JVM internals, I want to understand these two stages properly.

# 2. What Is Compilation?

Compilation is the process of translating source code into another form that can be processed or executed by a computer.

In Java, the compiler is called `javac`.

When I write a Java program, I save it with the `.java` extension.

For example:

```java
public class Main {

    public static void main(String[] args) {
        System.out.println("Hello Java");
    }

}
```

I save this file as:

```text
Main.java
```

This is called Java source code.

The source code is written in a language that developers can understand and work with.

However, the JVM does not directly execute this `.java` source file in the normal compilation workflow.

The Java compiler translates this source code into Java bytecode.

## 2.1 When Does Compilation Actually Happen?

This was one of my main doubts.

Does Java compile my program when I am writing code or when I save the file?

**No, saving a file does not automatically mean that compilation has happened.**

Saving simply stores my source code on the computer.

Compilation happens when I invoke the Java compiler, either manually or through an IDE or build tool.

For example, suppose I have:

```text
Main.java
```

I open the terminal and execute:

```bash
javac Main.java
```

Now the Java compiler starts compiling my source code.

If compilation is successful, it produces:

```text
Main.class
```

The `.class` file contains Java bytecode.

Important distinction:

- Writing code means creating the source code.
- Saving code means storing the source code.
- Compiling code means translating and checking the source code.

These are three different activities.

## 2.2 What Happens During Compilation?

When I execute:

```bash
javac Main.java
```

The compiler performs several checks and operations.

For example:

- It checks Java syntax.
- It checks data types.
- It checks whether variables and methods are used correctly.
- It checks whether referenced members are accessible.
- It generates bytecode if compilation succeeds.

Consider this example:

```java
public class Main {

    public static void main(String[] args) {

        int age = "20";

    }

}
```

This program contains a type mismatch.

I am trying to assign a String value to an integer variable.

The compiler detects this problem and reports a compilation error.

The program cannot proceed through the normal compilation and execution process until this error is fixed.

# 3. What Is Java Bytecode?

After successful compilation, Java produces a `.class` file.

This file contains something called **Java Bytecode**.

Bytecode is an intermediate instruction format generated by the Java compiler.

It is not the original Java source code, and it is not ordinary native machine code for a particular processor.

For example:

```text
Main.java
    |
    | javac Main.java
    |
    v
Main.class
```

The `.class` file contains bytecode instructions that the JVM understands.

## 3.1 Why Does Java Use Bytecode?

Imagine two computers:

- Computer A runs Windows.
- Computer B runs Linux.

Their operating systems and underlying environments are different.

If Java generated only Windows-specific machine code, that program would not automatically run on Linux.

Java solves this problem by generating platform-independent bytecode.

The JVM available on each platform handles the execution of that bytecode.

```text
             Main.java
                 |
                 v
             javac
                 |
                 v
            Main.class
            (Bytecode)
             /       \
            /         \
           v           v
      Windows JVM   Linux JVM
           |           |
           v           v
        Execution   Execution
```

The same compiled Java bytecode can run on different platforms, provided a compatible JVM is available.

This is the basic idea behind Java's platform independence.

**Remember:**

Write Once, Run Anywhere.

This does not mean that every Java program is automatically compatible with every platform. Native libraries, operating-system dependencies, and incompatible Java versions can introduce limitations.

# 4. What Is Runtime?

Compilation and execution are not the same thing.

After successful compilation, the program still needs to be executed.

This is called runtime.

For example, after compiling:

```bash
javac Main.java
```

I can execute:

```bash
java Main
```

This command launches the Java application using the JVM.

The JVM loads and executes the compiled classes.

The output will be:

```text
Hello Java
```

## 4.1 Compile-Time vs Runtime

This distinction is extremely important because I will encounter these terms frequently in OOP, especially in polymorphism and method overriding.

### Compile-Time

Compile-time refers to the compilation stage.

At this stage, the compiler checks whether the source code follows Java's language rules.

Examples include:

- Syntax errors
- Type mismatches
- Undefined variables
- Invalid method calls
- Access modifier violations

Example:

```java
public class Main {

    public static void main(String[] args) {

        int age = "20";

    }

}
```

This code produces a compilation error because a String cannot be assigned to an int variable.

The program cannot successfully compile in its current form.

### Runtime

Runtime refers to the period when the compiled program is actually executing.

At this stage:

- Objects are created.
- Methods are executed.
- Variables are accessed and modified.
- Calculations are performed.
- Exceptions may occur.

Consider:

```java
public class Main {

    public static void main(String[] args) {

        int a = 10;
        int b = 0;

        System.out.println(a / b);

    }

}
```

This program can compile successfully.

Why?

Because the syntax and types are valid.

However, when Java executes the division operation, an `ArithmeticException` occurs.

This is a runtime exception.

### The Difference

| Compile-Time | Runtime |
|---|---|
| Happens during compilation | Happens during program execution |
| Compiler checks the source code | JVM executes the compiled program |
| Detects compilation errors | Can encounter runtime exceptions |
| Example: assigning String to int | Example: integer division by zero |
| Program must compile successfully before normal execution | Program has already entered execution |

**My mental model:**

Compile-time answers:

"Is this code valid according to Java's compilation rules?"

Runtime answers:

"What actually happens when this program executes?"

## 4.2 Can an Error Occur at Runtime Even If Compilation Succeeds?

Yes.

Compilation does not guarantee that the program will execute successfully.

For example:

```java
public class Main {

    public static void main(String[] args) {

        String name = null;

        System.out.println(name.length());

    }

}
```

This program can compile successfully.

However, during execution, Java tries to call `length()` on a null reference.

This produces a `NullPointerException`.

This is another example of a runtime exception.

# 5. Understanding JDK, JRE and JVM

These three terms are frequently used in Java.

I want to understand how they are different instead of memorizing their definitions.

## 5.1 JVM — Java Virtual Machine

JVM stands for Java Virtual Machine.

It is the virtual machine responsible for executing Java bytecode.

When I execute:

```bash
java Main
```

The Java launcher starts the JVM, which loads the required classes and executes the program.

The JVM is responsible for important operations such as:

- Loading classes.
- Verifying bytecode.
- Managing runtime memory.
- Executing bytecode.
- Managing garbage collection.

The JVM is also the reason Java bytecode can run on different operating systems that have compatible JVM implementations.

## 5.2 JRE — Java Runtime Environment

JRE stands for Java Runtime Environment.

Conceptually, it provides the environment required to run Java applications.

It includes the JVM and the required runtime libraries and supporting components.

Its purpose is to provide what is needed for running Java applications, rather than developing and compiling them.

Note: Modern Java distributions do not always provide a separate traditional JRE installation. Runtime environments can be assembled using modular Java tools.

## 5.3 JDK — Java Development Kit

JDK stands for Java Development Kit.

It provides the tools required to develop Java applications.

It includes:

- Java compiler (`javac`).
- Java launcher (`java`).
- Other development tools.
- Runtime components, including the JVM and Java libraries.

If I want to write, compile, and execute Java programs, I generally install the JDK.

## 5.4 Relationship Between Them

A useful conceptual relationship is:

```text
             JDK
              |
       Development Tools
              |
        +-----+-----+
        |           |
      javac       java
                    |
             Runtime Components
                    |
                   JVM
                    |
             Java Libraries
```

**Remember:**

- JVM: Executes Java bytecode.
- JRE: Provides the runtime environment.
- JDK: Provides development tools and runtime components.

# 6. How Does the JVM Execute Java Bytecode?

Now that I understand compilation, bytecode, and runtime, I can explore what happens inside the JVM.

The JVM has several important components involved in executing a Java application.

The main components I want to understand are:

1. Class Loader
2. Bytecode Verifier
3. Runtime Data Areas
4. Execution Engine
5. Garbage Collector

## 6.1 Class Loader

Before the JVM can execute a class, it needs to load that class.

The Class Loader subsystem loads compiled class files into the JVM.

For example, when I execute:

```bash
java Main
```

The JVM needs to load the `Main` class before executing its `main()` method.

Class loading involves three broad stages:

- Loading: Finds and loads the class's binary representation.
- Linking: Performs verification, preparation, and resolution.
- Initialization: Executes class initialization code, including static field initializers and static blocks.

I will study static initialization more deeply in the Static and Final lesson.

## 6.2 Bytecode Verifier

After class loading, the JVM performs bytecode verification as part of the linking process.

The verifier checks whether the bytecode follows JVM rules.

It helps ensure that the bytecode is structurally and type-safe according to the JVM specification.

This is important because the JVM must not blindly execute arbitrary invalid bytecode.

## 6.3 Runtime Data Areas

The JVM uses different memory areas while executing a Java application.

Some important areas include:

**Heap**

- Stores objects and arrays.
- Shared among threads.
- Managed by the garbage collector.

**Java Stack**

- Each thread has its own Java stack.
- Stores method frames.
- Each frame contains information such as local variables and intermediate computation results.

**Method Area**

- A logical runtime area containing class-level structures, such as runtime constant pools, field and method information.
- Its implementation in HotSpot is associated with Metaspace.

**PC Register**

- Each thread has its own program counter register.
- It keeps track of the current JVM instruction being executed for that thread.

**Native Method Stacks**

- Support execution of native methods.

Important: These are JVM runtime memory areas. The exact implementation and physical memory layout can differ between JVM implementations.

## 6.4 Execution Engine

After the necessary classes have been loaded and verified, the JVM executes their bytecode.

The execution engine has important components:

**Interpreter**

Executes bytecode instructions.

It can start executing methods without first compiling the entire application into native machine code.

**JIT Compiler**

JIT stands for Just-In-Time Compiler.

Frequently executed portions of code can be compiled into native machine code during runtime.

This helps improve performance.

**Garbage Collector**

The garbage collector automatically reclaims heap memory occupied by objects that are no longer reachable.

I will study memory management and garbage collection in more depth when learning Java memory and object references.

# 7. What Happens When I Click the Run Button in IntelliJ IDEA?

Until now, I have used an IDE to execute my programs.

I want to connect everything I have learned to my actual development workflow.

Suppose I have:

```text
Main.java
```

When I click the green Run button in IntelliJ IDEA, the IDE generally performs these operations:

1. It checks the configured project and run configuration.
2. It compiles the required source files, or uses existing valid build output where possible.
3. It generates or updates the corresponding `.class` files.
4. It starts the Java application using the configured Java runtime.
5. The JVM loads the required classes.
6. The JVM executes the `main()` method.
7. The output appears in the Run window.

The important point is that the IDE is handling many operations behind the scenes.

I do not necessarily have to type `javac` and `java` manually every time.

## 7.1 Does Saving Automatically Compile My Code?

Not necessarily.

Saving a `.java` file simply saves its contents.

However, some IDEs have background compilation or automatic build features.

For example, IntelliJ IDEA can perform background analysis and may compile files automatically depending on its settings.

Therefore, I should distinguish between:

- Saving: Stores source code.
- Background analysis: Checks code and reports problems while I work.
- Compilation: Produces compiled output.
- Execution: Runs the program.

These operations may happen close together in an IDE, but they are not the same thing.
